# Configuration

Fall Line has no runtime configuration surface (no accounts, no server); everything below is a URL parameter, build-time, or repo plumbing.

## URL parameters

The running game reads its situation off the URL, which is what makes a map a link and a bug report a repro:

| Parameter       | Meaning                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `seed`          | Which mountain to build (an integer). The same seed is the same face, forest, piste, gates, start and sun hour on every machine. Pins the front door's races (the SLALOM, the SUPER-G and the DOWNHILL) and the TIME TRIAL to it — a slalom off a seed of its own built to a RED piste unless `grade` says otherwise, because a slalom is never set on an easy hill; a downhill off one is set on the ski area's course with the most vertical (R32), and a super-G on the same course from a start lowered into its band (R33). |
| `start=slalom`  | Boot straight into a SLALOM in the start house — run one of two, the field of thirty already down — the attract card and the front door skipped (`start=race` and `start=1` are the same, and the developer page's REPRO line writes `start=race`). |
| `start=downhill` | ...or into a DOWNHILL's TRAINING run in its start house — the field of thirty already down (`run=2` the RACE after it). |
| `start=superg`  | ...or into a SUPER-G's one run in its start house — the field of thirty already down. |
| `start=gs`      | ...or into a GIANT SLALOM's first run in its start house — the field of thirty already down; `run=2` its second run. |

A lab's and a link's; `make screenshots ARGS="--hold 15,40 --move check"`.                                                                                 |
| `shot=1`        | ...held still once drawn, so nothing moves under a screenshot's shutter.                                                                                                                                                                                                                                                                                                                                                                                                     |
| `paused=1`      | ...or held under the pause card.                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `mode=trial`    | The run a link boots into (and the next one pressed) is a TIME TRIAL — alone, against the record and its ghost — rather than a slalom; `mode=downhill`, a DOWNHILL (as `start=downhill`); `mode=superg`, a SUPER-G (as `start=superg`); `mode=gs`, a GIANT SLALOM (as `start=gs`); `mode=speedski`, a SPEED RACE (as `start=speedski`); `mode=skicross`, a SKI CROSS (as `start=skicross`); `mode=bigair`, a BIG AIR contest (as `start=bigair`); `mode=knuckle`, a KNUCKLE HUCK (as `start=knuckle`); `mode=slopestyle`, a SLOPESTYLE contest (as `start=slopestyle`); `mode=railjam`, a RAIL JAM (as `start=railjam`); `mode=halfpipe`, a HALFPIPE contest (as `start=halfpipe`); `mode=moguls`, a MOGULS contest (as `start=moguls`); `mode=dual`, a DUAL MOGULS contest (as `start=dual`); `mode=aerials`, an AERIALS contest (as `start=aerials`). |

| `poles=0`       | The player's runs this visit skied WITHOUT POLES (the hard mode — `poles=1` with them), over the DRESS card's POLES row and never written back; the developer page's REPRO line carries it.                                                                                                                                                                                                                                                                                  |
| `bot=1`         | The player's own skis skied by the bot for the whole run, not just the pre-roll — a run watched to its finish plate with nobody's hands on it.                                                                                                                                                                                                                                                                                                                               |

| `menu=root`     | Open on the front door rather than the attract card; `menu=skis` the ski card, `menu=start` the free ride's start card, `menu=options` OPTIONS, `menu=keys` its KEYS page, `menu=gallery` the GALLERY, `menu=campaign` the campaign card, `menu=races` the race card, `menu=levels` the level card (with `mode=trial` for a TIME TRIAL's, `mode=superg` the super-G's nine), `menu=tricks` the trick map card; `menu=dev` the DEVELOPER page (let out, as the title's hold lets it out), `menu=unlocks` and `menu=benchHistory` behind it. |
| `region`        | Build the seed's mountain in this kind of snow country (R21) — `alpine`, `fell`, `continental`, `maritime` — for a free ride (over the start card's COUNTRY row) and a slalom or time trial a `seed` link boots into; never a campaign map, which is pinned.                                                                                                                                                                                                                                 |

| `sled`          | `1` — a free ride (`start=free`) begun ON THE SNOWMOBILE, stood on its boards at the bottom with the skis racked (`sled.ts`), over the start card's RUN row. Loses to `heli`. |
| `para`          | `1` — a free ride (`start=free`) begun UNDER THE PARAMOTOR, stood on the summit with the wing held overhead and the motor on his back (`para.ts`), over the start card's RUN row. Beats `heli` and `sled`. |
| `afterski`      | `1` — a free ride (`start=free`) begun INSIDE the valley's afterski lodge (`afterski.ts`), the party under way and his skis in the rack. Beats every other start. |
| `buzz`          | `0..1` — a free ride (`start=free`) begun with that BUZZ (`buzz.ts`), as though he had been to the afterski already. |
| `grimbear`      | `1` — a free ride (`start=free`) the GRIMBEAR hunts (`grimbear.ts`), over the odds the app deals him by (`GRIMBEAR_ODDS`, one ride in three); `0` — one he never shows on. |
| `groomer`       | `1` — a free ride (`start=free`) the PISTE MACHINES work whatever the hour (`groomer.ts`); `0` — one they never do. Left out, they are out after dark (`GROOMER.night`). |
| `weather`       | Ski the mountain under this sky instead of the one R19 dealt it — `clear`, `fair`, `flurries`, `high`, `overcast`, `snow`, `storm`, `fog` (`withSky`); the mountain itself is the seed's.                                                                                                                                                                                                                                                                                    |
| `hour`          | ...and from this solar start hour, 0–24 — how a lab stands a run in the dark.                                                                                                                                                                                                                                                                                                                                                                                                |
| `video`         | Draw this visit at a picture preset — `low`, `medium`, `high` — without storing it: how a lab meters or photographs a rung.                                                                                                                                                                                                                                                                                                                                                  |
| `picture=r:s,…` | Ski this visit with these picture rows at these stops (`distance:low,shadows:off`), laid over the preset and never stored — how `make bench --costs` prices one row at a time.                                                                                                                                                                                                                                                                                               |
| `probe=0`       | Do not time the machine on this visit: AUTO's probe may move the picture, and a lab wants it held still.                                                                                                                                                                                                                                                                                                                                                                     |
| `splash=1\|0`   | Force the attract card up, or off an ordinary visit.                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `bench=1`       | Run DEVELOPER ▸ BENCHMARK the moment the app is up — how `make bench` takes a score off the built site.                                                                                                                                                                                                                                                                                                                                                                      |
| `gpu=passes`    | ...with the GPU's own timer (`gpu-timer.ts`, where the browser has `EXT_disjoint_timer_query_webgl2`) cutting every frame into its render passes — the default; `gpu=split` cuts the scene's pass by subsystem too (dishonest on a tiled GPU), `gpu=off` times nothing.                                                                                                                                                                                                      |
| `hide=a,b`      | ...drawn WITHOUT these subsystems (`HIDEABLE`: sky, terrain, forest, field, checkpoints, cloud, spray, snowfall, wildlife, shadow, hero, trail) — an A/B reading, never a score.                                                                                                                                                                                                                                                                                             |
| `frames=n`      | ...timing `n` frames (60 up to the plan's 1800) instead of the plan's: a price list's shorter stretch.                                                                                                                                                                                                                                                                                                                                                                       |
| `view=vista`    | ...with the lens planted high on a side ridge looking across the whole mountain: the view DISTANCE is dearest from, which `make bench --costs` prices every stop from as well as the race's.                                                                                                                                                                                                                                                                                 |
| `ab=1`          | ...hiding each subsystem a frame in turn and billing what each one cost the GPU as the difference — the interleaved A/B `make bench ARGS="--gpu --ab"` prints.                                                                                                                                                                                                                                                                                                               |
| `update=1`      | Draw the new-build button as if a build were waiting.                                                                                                                                                                                                                                                                                                                                                                                                                        |

`pwa/src/game/url-params.ts` is the reading of all of them; it, this table and `scripts/screenshot.mjs` move together.

## What the game remembers

One blob, in `localStorage` under `fall-line.settings.v1` (`pwa/src/game/settings.ts`): the camera rung the skier last chose, the pair last picked on the ski card, the outfit worn (`outfit`: a body, its weight — the build the engine skis him at, `light`, `medium`, `solid` or `heavy` (`engine/game/defs/riders.ts`) — a jacket, pants, a helmet, gloves and poles — `none` the hard mode, skied without them — each an id in `pwa/src/game/outfit.ts`'s catalog — an unknown one is the default kit's piece; a pair's topsheet is its own and nothing of it is kept), whether the sound is on, and every row of OPTIONS — the three faders (master, wind, effects), the picture (`pwa/src/game/settings-video.ts`: resolution, distance, terrain, trails, forest, shadows, spray, antialiasing), the key bindings, the thumbs (the lever's side, the travel, the inverted lean), the two assist dials, the damage switch and whether the HUD is up — the time trial's length (always one run), the pinned map the time trial's level card last picked (`level`, a campaign map's id), the race map each discipline's level card last picked (`raceMap`, one id per discipline — `pwa/src/game/race-maps.ts`), the map the trick map card last picked (`trickMap`, a trick map's id — `pwa/src/game/trick-maps.ts`), the jump an aerials contest declares off the same card (`aerialPlan`, a code of the chart — `engine/game/defs/aerial-jumps.ts`), the start card's free ride (`pwa/src/game/free-ride.ts`: the mountain, the season and the time of day — each null until moved, which is the mountain's own — the sky, the snow (one of four depths), the country the mountain is raised in, the grade its piste is built to — null until moved, which is the seed's own — the run picked on the RUN row with the seed and country it was picked on — null, the first run of the grade; `heli`, the row's last stop, the helicopter, `sled` and `para` the snowmobile and the paramotor before it — and the spot picked on the chart with the seed it was picked on), whether the first-visit probe has had its say and whether the picture is AUTO's to fit (`autoPicture`), and the DEVELOPER page: whether it has been let out and its six instrument switches. It is merged field by field and a stored value this build does not offer is dropped for the default rather than trusted.

**The record book** is a second blob, under `fall-line.records.v1` (`pwa/src/game/records.ts`): one row per mountain seed and course, pair and mode (and the run count, always one) — and per slalom RUN, the second run being a course of its own (its row's id ends `/run2`; a first run's keeps the id every row had before a second run could be skied) — and per build of skier, a heavier one being faster downhill (`rider`: the medium build's rows carry no build and keep the ids they had before one could be chosen, and a ghost carries the build it was skied at) — the best time, the pair, the date it was set and the clock at every gate of that run (what the HUD's **VS BEST** chip is read against). Every row is checked on the way in and one no run could have set is dropped. **The ghosts** are one key each, `fall-line.ghost.v1:<row>` (`pwa/src/game/ghost.ts`): the time trial's record run as the controls that skied it — five run-length-encoded streams, a few kilobytes a run — with a fingerprint of the mountain it was skied on, so a tape for a mountain the generator has since moved is never put back on the snow. A tape over 400 000 characters is not kept, and a store that will not take either leaves the row standing for the session. Nothing else is written beyond what the service worker caches to play offline.

**The campaign's board** is a third blob, under `fall-line.campaign.v5` (`pwa/src/game/campaign.ts`; its map ids are the shelves' — `rime-1` … `crest-6` — and v5 is the ladder whose race rungs became SLALOMS, so a board kept under an older key, won on other maps or against another field, is left where it lies and not read): per map id, the best time, the pair that set it, the best place and the best medal, and — on a slalom — the points the whole field was paid by the better afternoon, booked at the first run's flag. Ids this ladder does not have and figures no run could have set are dropped on the way in.

**The benchmark's history** is a fourth blob, under `fall-line.benchmarks.v1` (`pwa/src/game/benchmark-history.ts`): the last twenty finished DEVELOPER ▸ BENCHMARK runs, newest first, each kept WHOLE — the score, the buffer, the picture it was drawn under, every reading and its cost, the scene and the run's totals — so any one run's report can be copied again. A run that is not one is dropped on the way in; a full store drops the oldest.

A free ride keeps no record and no ghost: its runs are not comparable (`keepsRecords`).

**The cloud save** (the store app on iOS only; `pwa/src/game/cloud-save.ts`, driven by `use-cloud-sync.ts`) carries the record book, the ghosts, the campaign's board and the skier's half of the settings to the skier's other devices, as one blob in the iCloud key-value store under the Apple ID the device is signed into — no account of the game's own, nothing sent anywhere else. It is merged, never overwritten: the better row per record, the faster tape per row, the further campaign, and for the settings the side changed LATER — every carried row but the picture (`video`, `probed`, `autoPicture`), the thumbs (`touch`) and the developer page (`developer`, `dev`), which are facts about the machine and never leave it. The one thing it keeps of its own is `fall-line.cloud.v1`: the moment the skier last moved a carried setting on this device. Ghosts go up smallest first while the save stays under 900 000 characters; one that does not fit stays on the device, its time still in the book. In a browser none of this runs and nothing is written.

**The start card's charts** are IndexedDB too, in a database named `fallline-charts-<generator>.<format>.<version>` (`seed-store.ts`): one record per map asked for (`<region>:<grade>:<seed>`) holding its two pictures, its schematic and its runs, so a mountain seen before is on the card at once. **Eighty kept**, the oldest pruned on every write. A chart is only ever read by the build that painted it: the database's name carries the generator version, the shape of the record and the app's version, and every other build's database is deleted when the card first opens one. It is never load-bearing either — with no IndexedDB the card builds every chart as it always did.

**The screenshot roll** is not in `localStorage` at all: a picture is hundreds of kilobytes of PNG, so it lives in IndexedDB, in a database named `fallline-shots` (the framework's `shots/shot-store`), one record per picture — its id, when it was taken, its size, its caption and the PNG. Newest first, **forty kept**, the oldest pruned off the disk by key on every new picture (the framework's `shots/shot-roll`). It is never load-bearing: a browser with no IndexedDB (a private tab, storage switched off) keeps the roll in memory for the life of the tab, and a picture is never lost over a store that would not open. Nothing is read from it until the GALLERY is opened.

**The picture fitted to the machine (PRESET ▸ AUTO).** While PRESET is AUTO (as a fresh visit is), the game times itself drawing the run under the front door for a second (`pwa/src/game/video-probe.ts`) and fits every picture row to what it measured (`pwa/src/game/picture-fit.ts`). The aim is sixty frames a second with as little of the look given up as possible. Every stop of every row carries a COST (ms a frame on a reference machine, measured with `make bench ARGS="--gpu --costs"`) and a BENEFIT (what it adds to the look, on one scale for every row). Over budget, the fit drops the step that loses the least benefit for each millisecond it saves; with room, it adds the step that buys the most. The measured frame scales the reference to this machine, so the probe applies its answer, times that picture again and fits again, up to three rounds. It runs once a visit and again the moment AUTO is pressed. Moving any row by hand, or pressing a preset, makes the picture the skier's and stops it. It never runs over a run, and `?probe=0`, `?video=` or `?picture=` hold it off.

## Installing

Every dependency resolves from the public npm registry, so `npm install` needs no token and no `~/.npmrc` entry.

## Build-time environment

| Variable                           | Meaning                                                                                                                                                                                                                |
| ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `VITE_BASE`                        | Deploy base path: `/` (default), `/preview/`, `/branch/`. Drives the SW scope, the manifest identity, and every emitted URL.                                                                                           |
| `VITE_PWA_IGNORE_PATHS`            | Comma-separated absolute paths the built service worker must NOT claim. Only the root slot sets it (`/preview/,/branch/`) so nested slots own their own pages.                                                         |
| `GITHUB_SHA` / `GITHUB_RUN_NUMBER` | Provided by CI; baked into the build label the HUD corner shows.                                                                                                                                                       |
| `CHROMIUM_PATH`                    | The browser the screenshot and profile tools drive. Claude web sessions have one at `/opt/pw-browsers/chromium`.                                                                                                       |
| `BLENDER`                          | The Blender executable `make blender` runs (else the macOS app, else `blender` on the PATH). Only the Blender lab reads it.                                                                                            |
| `VITE_MODEL_SKIS`                  | `0` (or `off`) switches back to the code-built skis; unset, empty or anything else draws the modelled ones (`pwa/models/<id>.glb`, packed as `models/<id>.glb`). CI hands it the repository variable of the same name. |
| `VITE_MODEL_HELI`                  | `0` (or `off`) packs no helicopter model and the free ride's helicopter is drawn as the code's stand-in (`heli-view.ts`); unset, empty or anything else packs `pwa/models/heli.glb` as `models/heli.glb`. |
| `VITE_MODEL_SLED`                  | `0` (or `off`) packs no snowmobile model and the free ride's snowmobile is drawn as the code's stand-in (`sled-view.ts`); unset, empty or anything else packs `pwa/models/sled.glb` as `models/sled.glb`. |
| `VITE_MODEL_GROOMER`               | `0` (or `off`) packs no piste machine model and the free ride's night groomers are drawn as the code's stand-in (`groomer-build.ts`); unset, empty or anything else packs `pwa/models/groomer.glb` as `models/groomer.glb`. |

`.env.example` at the root documents the same set; copy it to `.env` (gitignored) to override locally — the build reads the root `.env` (`envDir` in `pwa/vite.config.ts`) for the client's switches and the packing alike, and the environment wins over it.

**The modelled skis.** Unless the switch turns them back, the game draws the glTFs committed in `pwa/models/` (made by `make models` — Blender, off the game's own spec and traces; see the `blender-assets` skill; `tests/models_test.ts` fails when one is older than its sources) instead of the code's drawn skis, and nothing else changes: the physics, the pose, the lamps, the thrown skier and every reader of a pair are the code's; a model is dressed in the pair's topsheet (its colours, not its pattern's decals) and posed off the same readings. Nothing else is a model. THE SKIER is DRESSED in code: his outfit (`outfit.ts` — the body, jacket, pants, helmet, gloves and poles picked on the DRESS card, each in its own colours) cut onto the rig in its bind pose and skinned on its bones (`dress-loft.ts`, `skier-dress.ts`; the `skier-gear` skill, `make gear`). The TREES are built procedurally by the code (`tree-shapes.ts`, off `tree-variants.ts`' rows) at three levels of detail, each trunk drawn to its tree's age (`TreeDef.radius`), painted per map in the region's colours; the FOREST row decides how many variants of each kind are drawn. The BIRDS and the ANIMALS are built procedurally too, in the same chunky, faceted look (`bird-shapes.ts`, `beast-shapes.ts`, off the roster's rows and the species' styles), at a near and a far cut, in the forms a species shows (a cock and a hen, a first-winter bird, a calf), each one an individual (`wild-traits.ts`: its size, shade and rack, hashed off its group's own scatter) moved by shader hinges — a wing's flap and fold, a leg's swing, a head's graze, the antlers grown to the animal's age; the FOREST row decides how many forms of a species are drawn and where the near cut hands over (`FOREST_LOOK[row].wild`), never how many species. The COURSE'S MARKS (the gate pole and its panel, the edge pole, the marker, the start hut, the finish arch round the line's own plan) are built the same way (`mark-shapes.ts`). The model files are fetched with the renderer, before any pair is built, and precached by the service worker with the rest of the build. **Switching back** is `VITE_MODEL_SKIS=0` for a local build (or the root `.env`), and for every CI build — the site's slots, a release, the desktop and store apps — the repository variable of the same name, which every workflow's build step hands on: `make ci-models MODELS=off` sets it to 0 and the next deploy draws the code-built skis, with no commit; `MODELS=on` puts the models back.

The platform shells (`tauri/`, `native/`) each bring an environment of their own, read neither by the website's build nor by each other: the desktop app's launch-time `SH_GAME_URL` (point the window at a deploy slot instead of its bundled copy), and the store app's `native/.env` (`native/.env.example` documents it — the store identifier, the Expo project, the signing team, and `EXPO_PUBLIC_CLOUD_SAVE=off` to drop the iCloud entitlement from a local build). See [platforms.md](platforms.md).

## The deploy slots

`pages.yml` builds three whole sites and merges them into one Pages artifact served at `game5.niclaslindstedt.se` (the custom domain in `pwa/public/CNAME`; DNS is a CNAME on `niclaslindstedt.github.io`, and the repo's Pages settings must say "GitHub Actions" + that domain):

- `/` — the highest `v*` tag (or `main` before the first release), with `VITE_PWA_IGNORE_PATHS` set so its service worker disowns the nested slots.
- `/preview/` — the triggering `main` commit, every push.
- `/branch/` — parked by `workflow_dispatch` with a `branch_ref` input; persisted in the `branch-deploy` orphan branch so ordinary deploys carry it forward until the next dispatch overwrites it.

Each slot's manifest gets a distinct `id`/`scope`/`start_url` and install name (`Fall Line`, `Fall Line (preview)`, `Fall Line (branch)`), and each slot's service worker its own precache (`cacheIdForBase` in `pwa/src/app-pwa.ts`: `fall-line`, `fall-line-preview`, `fall-line-branch`), so side-by-side installs don't collide.

## Releases

`version-bump.yml` (manual dispatch, and the only entry point) checks the branch and the tree, prints the version it is about to cut, and calls `release.yml`, which derives the bump from `.changes/unreleased/` fragments, rewrites every version string via `scripts/update-versions.sh`, collates the CHANGELOG, commits `chore(release): vX.Y.Z`, tags, creates the GitHub Release as a draft, publishes it, and chains into `pages.yml` so `/` serves the new tag immediately. It is one dispatched run under the default `GITHUB_TOKEN` — no PAT. The desktop shell's packaging matrix (`release.yml`'s `desktop` job) runs between the draft and the publish, which waits until every platform's download is attached.

Every surface that cannot import the module restates what it needs: `pwa/index.html` (the title and the theme colour — deliberately carrying no crawlable copy, see _Discoverability_), `pwa/public/` (CNAME, robots, the privacy and support pages), `scripts/generate-icons.mjs` (the palette the icons are painted in) and the two `package.json` descriptions. `tests/identity_test.ts` holds every one of them to the module, so a rename or a palette change is one edit and a failing test naming the copies.

## Discoverability

**The web deploy is not indexed, on purpose.** The site is the game's free, incomplete cut; it is not meant to be found through a search engine or to unfurl as a card in a chat client, so it emits none of the signals that would make either work:

| Surface                             | What it carries                                                                                                                                                                     |
| ----------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `pwa/index.html` head               | `noindex,nofollow,noarchive,nosnippet,noimageindex` and nothing else a crawler reads: no meta description, no canonical, no sitemap link, no Open Graph or Twitter card, no JSON-LD |
| `pwa/index.html` body               | `#root` and a `<noscript>` line. No prerendered copy describing the game                                                                                                            |
| `pwa/public/robots.txt`             | `Disallow: /`, advertising no sitemap                                                                                                                                               |
| `sitemap.xml`, `llms.txt`, `og.png` | not shipped, and not generated                                                                                                                                                      |
| `privacy/`, `support/`              | still REACHABLE — a store review fetches them by URL — but `noindex,nofollow` and no canonical                                                                                      |

`robots.txt` alone would only ask a crawler not to fetch; a URL it already knows can still be listed. The per-page `noindex` is what covers that, which is why both are there. `tests/identity_test.ts` holds all of it: adding a discovery tag, a crawler file or prerendered body copy back fails the suite.

This is a deliberate deviation from OSS_GAME_SPEC §11.3, recorded as such in [spec-conformance.md](spec-conformance.md).
