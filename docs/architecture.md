# Architecture

Fall Line follows the shape of its sibling repos: a headless engine that IS the game, a thin browser shell that draws it, and tooling that measures it. One direction of dependency:

```
tests/  scripts/(sim, the labs)            pwa/ (Preact + three.js shell)
        \                                   /
         `----------->  engine/  <---------'
           (framework-free TypeScript — imports nothing but itself
            and @niclaslindstedt/oss-game-framework's core/ and racing/)
```

The generic parts every sibling game shares — the engine-safe pool (the PRNG, the math, noise, heightfields, quaternions, the sun, the output sink), the racing primitives (the control tape, the record book's policy, the standings), the synth, the screenshot roll, the update watch, the input plumbing, the run clock and the lab shelf — come from [`@niclaslindstedt/oss-game-framework`](https://github.com/niclaslindstedt/oss-game-framework), a git dependency on a release tag. A bug in them is fixed there and pulled in by moving the tag. The engine may import only its `core/*` and `racing/*` (never `core/clock`); `tests/imports_test.ts` holds that line.

`tauri/` and `native/` — the desktop and store shells — stand beside these, outside the npm workspace ([platforms.md](platforms.md)); the one line of `pwa/` that knows either exists is `pwa/src/shell-host.ts`.

## `engine/` — the game, headless

A pure TypeScript module with no framework, no renderer, no DOM and no `node:` — it imports nothing outside its own tree but the framework's engine-safe `core/` and `racing/`, which is what lets the browser bundle, the headless simulator and the test runner host it unchanged. Its public surface is `engine/index.ts`, spelled `@engine` by every host.

- `createGame({ seed?, level?, mode?, heat?, rivals?, countdown?, contact?, spec?, region?, grade?, quiet? })` builds a run: the mountain the seed generates (or the one handed in — the tests and the labs stage synthetic ones), the player's skier standing on the start line's first slot, and the rules of its MODE (`MODE_RULES` in `game/defs/modes.ts`; each option still overrides its own rule). With no mode it is the field on the start line (`fieldRules`: `RACE.rivals` = 3 rivals on the other slots, one run, three seconds of lights) — the suite's, the labs' and the benchmark's run, and no mode the player picks. `mode: "slalom"` sets a SLALOM over the map (R31, `mapgen/slalom.ts`'s `setSlalom`; a seed of its own is built to a red piste unless `grade` says otherwise) and DEALS its start list instead of skiing it (`field.ts`) — `heat` carries the first run into the second, set afresh on the same stretch; `mode: "timeTrial"` is the lights and the piste with nobody else on it. A mode is a name for a bundle of `RunRules` and nothing in the engine branches on the name.
- `step(state, input)` advances exactly one fixed 120 Hz step (`TUNING.dt = 1 / TUNING.physicsHz`) and leaves that step's events on `state.events`. The app's frame loop and the headless simulator call this same function; there is no other way to advance a run.
- `placeRun(state, moment)` stands a run at a moment instead of skiing to it — a plan point, a heading, a speed, optionally a height, a climb, a pitch and a roll, and the lights still to run in front of it (`lights`) — with the skis flat and the body standing. The tests and the ride lab stage through it; the moment itself is still the engine's to emit.
- `botInput(state)` is the bot's answer for the same state (`sim/bot.ts`); `simulateRun(seed, options)` skis a whole mountain with it (`sim/simulate.ts`, [simulation.md](simulation.md)).

**Determinism is a hard invariant.** Everything random draws from the seeded stream in the state (`state.rng = createRng(seed)`, the framework's `core/prng`), never `Math.random`; `state.t` is the only clock the engine knows. The only draws a run makes are the rivals' paces and pairs at the start line, and — off a stream of the start's own seeded beside it, so the field a seed deals is untouched by it — how late each rival goes after GO (`RACE.reactBand`) and the phase his first stride lands on. A slalom draws nothing from the run's stream: its board is dealt off the map's seed on streams of the field's own (`field.ts`), and its gates off a stream of the run's own (`mapgen/slalom.ts`). A seed and a list of inputs reproduce a run to the bit, which is what the sim digests rely on and `tests/determinism_test.ts` holds.

### The step

`step.ts` runs, in order:

1. the clock (`t += dt`, `tick += 1`) and the input copied onto `state.input`;
2. THE LIGHTS: under `countdown` a `count` event as each of its seconds begins (three on the start line; a slalom's starter takes four), then `go` and the phase to `racing`;
3. THE PLAYER'S RUN (`run.ts`'s `stepRun`): on a free ride, the LIFT that carries him, if any (`lift-ride.ts`'s `stepLift`: taken into a load zone, taken to the carrier, carried up the rope, stood off at the top — the step is the lift's while it has him), and the lead off the free ride's own lift (`leadInput`: the input he is given toward the run he picked until he touches a control); a reset asked for; else the wind tunnel he rides, if any (`wind-tunnel.ts`'s `stepTunnel`: taken in, carried, let go), on an interval start the racer HELD in the start house after GO and thrown out of it when the tuck asks (`start-push.ts`: one push and a hop off it, timed by `SkierState.launch`; no skate and no double pole on such a run), the skier (`skier.ts`'s `stepSkier` — under the lights held on the line (and held IN the gate — the step's way over the snow taken out, however steep the pitch), after the finish with the controls let go — and, on a run that counts tricks, the strokes and the grab, `strokes.ts`), the trees and the map's edge (`collision.ts`), a slalom's flex poles knocked over and swinging back up (`gate-poles.ts`'s `stepGatePoles`: the `pole` event, a little speed for each knock), the wipeout — or, with the skier already off, his own body — a ragdoll — on the snow and the skis let go (`crash.ts`, `ragdoll.ts`) — the damage the step's blows cost on a run with damage on (`damage.ts`), what his body took (`body.ts`: the g of every blow, the injuries it did), the run's air record; and while racing, the run clock (on an interval start only once the wand is open — the clock waits for the racer), the buzzer (`RunRules.limit`), the course (`course.ts`'s `stepCourse`: the gate owed, the finish — or, under the STRICT gates, `strict.ts`'s `stepStrict`: the feet judged through every pole gate, and a gate missed, a pole straddled, a gate skipped or a start outside the window an `out` that ends the run) and the automatic reset (lying still, bogged — which waits longer — or once a thrown skier has lain long enough) — under the strict gates every reset, asked for or automatic, is a DID NOT FINISH instead (`course.ts`'s `outRun`): nobody is stood back on a slalom course;
4. THE SCORE (`tricks.ts`'s `stepTricks`), off the player's run's events: the air, the turns, the grabs, the landing judged (a clean or a perfect one an element of its own, `landingGrade`), the combo banked or lost;
5. THE FIELD (`rivals.ts`'s `stepRivals`): every rival's own run by the same `stepRun`, skied by the bot under the player's lights — none on an interval start, whose field (`GameState.field`) was dealt at `createGame` and is never skied;
6. SKIER AGAINST SKIER (`clipSkiers`), once every skier has moved;
7. THE CROWD, on a run whose rules ask for one (`RunRules.crowd` — the free ride's): the lifts first — every queue at a lift's foot shuffled up and its front taken by the carrier passing the load line, every rider carried on his carrier, every one let go at the top skating to his run (`crowd-lift.ts`'s `stepCrowdLifts`) — then every amateur's decision as it falls due and his way down his run (`crowd.ts`'s `stepCrowd`), then the player against them (`clipCrowd`: a `bump`, an amateur knocked down, a `skier` wipeout when it is hard).

### The state (`game/state.ts`)

`GameState` carries the map (`level`), the player's `skier`, the `input` last given, `progress` (the gate owed, the clock, the splits — and `out`, a `RunOut`: disqualified or did not finish under the strict gates, why — `missed`, `straddle`, `start` or `fall` — and at which gate; null while the run is in it or home), the `rules` (`RunRules`: rivals, the lights, contact, whether the course and the tricks count, the buzzer, how the field starts — `start`, `line` or `interval` — the gates' law — `gates`, `arcade` or `strict` — and the start `window`), the score (`tricks`, `TrickState`), the field (`rivals`, each a whole `GameState` of its own sharing the player's level, rules and stream), an interval start's field (`field`, `Field`: which run of the two, every racer's `FieldRun` in start order — his slot, his skis, his time or how he went out, the clock at every gate, the time carried in from the first run — and the player's own carried time and his slot in the order), a slalom's flex poles (`gatePoles`, `GamePoles`: every pole's tilt, its spin and the way it lies), the crowd (`crowd`, `CrowdState`: the free ride's amateurs and their groups, on a stream of their own), the `countdown`, the `phase` (`countdown` → `racing` → `finished`), the snow dial (`snowDepth`), the new snow the sky has laid (`fresh`), the help (`assist`), the damage switch and this step's `events`.

`SkierState` (also exported as `CraftState`) is what the renderer, the HUD and the audio read:

- the body: `x, y, z` (the CoG), `vx, vy, vz`, the orientation quaternion `q` (body → world; x right, y up, z forward), body rates `wx, wy, wz`, and `heading`, `pitch`, `roll` derived from `q` each step, with `incline` (the roll against the SNOW under him rather than the vertical — the angle between his body and the line his skis stand along, which the drawn pair reads to stay on the snow);
- the readouts: `speed` (|v|, vertical included, written once at the end of the step), `way` (along the skis, signed), `tuck`, `crouch` (the body's actual crouch after its lag), `brake`, `skid` (how far across the way the skis are pivoted), `steer`, `edge` (the angle the skis stand on, signed like the steer), `lean`, `skiAngle`, `packed` (the share of the load on groomed snow);
- the skier's weight: `hipRight` (the angulation into the turn), `hipAft` (fore and aft);
- the snow: `contacts` — every station (the tip, mid and tail of each ski, each named by its `station`) with its footprint on the snow surface, how deep it is pressed (`sink`, the track's depth), its width, its leg's `compression`, its `load` and whether it is `touching` — and `skiCompression` (left, right) for the legs as drawn;
- the air: `airborne`, `airTime`, `landing` (seconds since the last one);
- the wind tunnel: `tunnel` (the one he is carried along — its place, its id, where along it and how far off its line — or null);
- the lift: `lift` (`LiftRide`: the one he rides on a free ride — which, its kind, the phase `board` / `ride` / `lead`, his grip's place up the line and its speed, the carrier's swing on its hanger, the next tower, where he boarded from, and the free ride's lead onto the run he picked — or null);
- the start: `launch` (the seconds since he threw himself out of a slalom's start house, −1 before he has — what the start clip is timed by);
- the crash: `thrown` (the ragdoll's points once he is off), `stuckFor`, `trench` (how far he has sunk when bogged), `rolledFor`; the `damage` the skis and the legs have taken; the `body` — every part's worst injury, the injuries in the order taken, the blow on the g meter and the run's hardest.

`GameEvent`: `count`, `go`, `air`, `land` (air time, impact into the slope, `harsh`, the share of way `lost`), `hit` (a trunk, closing speed, where), `bump` (a rival), `checkpoint` (a gate: index, split), `missed` (and on a slalom gate the `penalty` it cost), `tunnel` (taken into a wind tunnel or let go: its id, `phase`), `lift` (on a lift: its id and kind, `phase` `board`, `tower` — a carrier over a tower's sheaves — `off` at the top, or `free` when the lead hands the controls back), `lap` (the finish line), `finish` (time, place), `out` (out of the race under the strict gates: the `RunOut`), `pole` (a flex pole knocked: its gate, how hard), `reset` (the gate, and whether the engine did it), `wipeout` (how: a trunk, over the tips, a fall, an edge caught), `stuck`, `damage`, `injury` (the part, which, its AIS rank — `body.ts`), and the score's `trick` (an element won), `combo` (a combo banked, `sketchy` on a harsh landing) and `bail` (one lost).

### By module

- **`game/step.ts`** — `createGame`, `rulesFor`, `step`. **`game/run.ts`** — one skier's step, the player's and every rival's alike. **`game/rivals.ts`** — the start line, standing and stepping the field, skier against skier, the standings (`raceProgress`, `racePlace`, `fieldOrder`, over the framework's `racing/standings`). **`game/defs/modes.ts`** — the modes and their rules (`MODE_RULES`; `fieldRules` and `RACE`, the field on the start line a run naming no mode is dealt), the SLALOM's (`slalomRules`, `SLALOM`: a start list of 29 beside the player, the starter's four seconds, the ten-second start window, two runs, the top 30 into the second, the slalom ski for the field; an interval start, the strict gates), the disciplines the game names (`DISCIPLINES`: the slalom built, the giant slalom, the super-G, the downhill, the ski cross and the speed run named and not yet built), the FREE RIDE's (`freeRules`: no field, no lights, `course` off — nothing owed, and a reset stands the skier on the nearest point of the nearest run) and the snow dial (`SNOW_DIAL`: `GameState.snowDepth`, the powder's sink as a multiple of the ordinary snow's, read by `snow.ts` and never drawing from the stream). The TRICKS run's (`tricksRules`: no field, `course` off, the strokes read, a buzzer of `TRICKS_RUN.limit`). A free ride can also be stood anywhere on the mountain (`course.ts`'s `freeSpawn`) and on another day (`mapgen/sun.ts`'s `withDay`, a copy of the level with only its sun moved — at an hour or at a named time of day, `hourOfTime`, whose NIGHT is past the daylight on purpose).
- **`game/skier.ts`** — one step of the rigid body: every force summed, then one semi-implicit integration ([riding.md](riding.md)) — the edge the steer asks for and the carve's curvature off the sidecut, the skid the brake pivots the skis into, the tuck's drag area and the crouch it lowers the body by, the hips' angulation and the fore-aft weight. **`game/suspension.ts`** — THE LEGS: the six stations' layout and the body's points, off the spec. **`game/snow.ts`** — the sink, the resistance and the grip an edge holds. **`game/poles.ts`** — the push at a crawl. **`game/flight.ts`** — the skier's levers in the air, and what a landing costs the legs. **`game/chassis.ts`** — the body's points (the hips, the shoulders, the helmet, the tips and tails) meeting the snow, as impulses. **`game/collision.ts`** — the trunks (hashed per level) and the map's edge. **`game/crash.ts`** — the wipeout: what throws the skier (a trunk, a landing over the tips, a fall at speed, an edge caught — the high-side), his body thrown, when the reset stands him up. **`game/trench.ts`** — the hole a stopped skier sinks into in deep powder, and poling and rocking out of it. **`game/damage.ts`** — what a blow dulls or hurts when damage is on, and the shares a hurt skier skis on. **`game/body.ts`** — what his body takes: every blow a stop over the body's give and the snow's, in g, the injuries off a risk curve per part (`defs/anatomy.ts`, the twenty parts and their ladders on the Abbreviated Injury Scale), the injury severity score, the g meter's blow — a readout the physics never reads. **`game/strokes.ts`** — the tricks run's strokes (the pump, the twirl) and the skier's grabs. **`game/tricks.ts`** — the score: what the air, the turns and the grabs are worth, the combo and the landing it is judged on ([riding.md](riding.md)).
- **`game/course.ts`** — the gates, the finish, the arrow (`bearingToNext`), a slalom gate skied past charged on the clock (`course.missPenalty`, `Progress.penalty`), the line through a course's slalom gates (`gateLineAt`, which the bot skis), the reset (`resetPose`, `standSkier` — on a free ride onto the nearest run of the resort). **`game/wind-tunnel.ts`** — the wind tunnels (R30): the ride (`stepTunnel`, before the skier is stepped — taken in, carried, let go, each with its `tunnel` event) and the wind (`tunnelWind`, `tunnelBlow`, summed with every other force in `skier.ts`: the air moving at the tunnel's speed, the blowers' thrust and the centring), `TUNING.tunnel`. **`game/lift-line.ts`** — a lift as a plan (R26): its towers on the ground, its rope (`planLift`, `ropeAt`, `liftPlans` once a map), its speed and each kind's load zone (`LIFT_LOOK`), and where carrier `k` is at the engine's clock (`carrierAt` — the lifts always run, a pure function of the clock, never stepped). **`game/lift-ride.ts`** — the lift ridden on a free ride (`RunRules.lifts`): boarded in its load zone (a chair's load line, a gondola station's door, a drag's track), carried — a chair's hanger swinging as a pendulum off a grip slowed into the terminal and kicked over each tower — stood off at the top (a chair onto its unload ramp, a gondola out of its station, a drag let go), and the free ride begun ON one when no spot was picked (`arriveByLift`: the last seconds of the lift, of any kind, serving the run picked — `freeRunOf` / `pickFreeRun` over `freeRuns`, the run named, else the first of the colour asked, else the course's first; `arrivalOf`) and led off its pad onto that run — skated across to it first where nothing a glide reaches joins it (`lead.cross`) — (`leadInput`: off a chair straight down the way off's lane past the house — `chairLane` — turned at the parting the way his run's sign points, round any station house and over the lip), `TUNING.lift`. **`game/limits.ts`** — what a skier CAN do, stated once for the physics and the bot: the terminal speed on a grade, the edge at a speed, the carve's curvature, the grip, the harsh speed. **`game/footprint.ts`** — a pair's footprint on the snow. **`game/place.ts`** — `placeRun`. **`game/clock.ts`** — where the sun and the moon stand over a run (at the map's hour, still for the whole run). **`game/snowfall.ts`** — the fall at a moment (`snowAt`: the squalls, the view it leaves) and the new snow it lays (`GameState.fresh`, stepped by `step`; the physics reads it through `snow.ts`'s `packedUnder` / `depthUnder`).
- **The slalom (R31)** — **`game/field.ts`** — an interval start's field: the start list dealt off the map's seed (every racer a skill and a grit, a time about the course's par, a share of DSQs and DNFs at gates dealt down the course), the first run's order (the best seeds drawn among themselves, then the rest, the player last), the second's (the first run's top `SLALOM.qualify` in reverse, the leader last; `Heat` carries the first run in), the bib (`startNumbers`), the standings on combined time (`fieldPlace`, `fieldOrderOf` — which `rivals.ts`'s `racePlace` and `fieldOrder` answer with on such a run). **`game/par.ts`** — the course's PAR (`slalomPar`): the clock a good racer takes down the racing line and at each gate, worked out off the pitch and what a pair can do on it rather than skied. **`game/strict.ts`** — the strict gates (`stepStrict`): both feet (the skis' mid stations) through every pole gate's line, a miss, a straddle or a skipped gate disqualifying, the start through the wand within `RunRules.window`. **`game/gate-poles.ts`** — the flex poles (`polePlan`, `freshGatePoles`, `stepGatePoles`): two hinged springs a gate, knocked by the line from his feet to his shoulders, a small speed loss, `TUNING.flex`. **`game/start-push.ts`** — the start push out of the house (`heldInHouse`, `stepStartPush`, `TUNING.start`).
- **`game/defs/`** — `skis.ts` (the catalog of six pairs and the reference pair), `tuning.ts` (every shared number, each with its unit, with `tricks.ts` folded in as `TUNING.tricks`), `modes.ts`.
- **`mapgen/`** — the world generator ([level-generator.md](level-generator.md)); its `query.ts` answers "where on the piste is this point nearest?" and "where is the piste this far down it?" for everyone, without wrapping — the piste is open. From v3 a seed builds a whole SKI AREA (R25–R30, stated in `resort-rules.ts` beside `rules.ts`), in the order `resort-build.ts` gives it: the massif (`massif.ts` — a peak, a shoulder and a bench), the lifts and the run slots (`resort.ts`), every run walked against an index of the ones laid before it (`network.ts` over `net-index.ts`, whose `covers` says whether a spot is on ANY run's surface), graded and pressed in that order (`network-build.ts`), the transport lanes routed across the face (`lanes.ts`) and linked between the sectors and to the lifts' feet (`links.ts`), ACCESS reckoned off the plan (`access-build.ts`, R29) and cured with link lanes and the drag lifts laid to a piste's foot (`drags.ts`), the HUB at the foot of the mountain and its two WIND TUNNELS (`hub.ts`, R29, R30), the woods by altitude (`resort-woods.ts`) and the courses down the network (`courses.ts`) — one of which the map is raced on, its slalom gates set either side of its line (`course-gates.ts`). A tricks run off a seed is built on the one-piste generator the trick maps stand on (`createGame`): a resort lays no park. A SLALOM is set OVER a built map rather than built into it (R31, stated in `discipline-rules.ts`'s `DISCIPLINE_RULES` beside the other two rule books): `slalom.ts`'s `setSlalom(level, run)` finds the stretch (`slalomStretch`: the steepest that drops a slalom hill's vertical, wide enough, crossing no drop, a gentler run-out for the finish arena), levels its kickers, clears its trees, cuts the start drop below the house, sets the pole gates in combinations — open gates, hairpins, verticals, delays — off a stream of the run's own and bakes the racing line (`slalomLineAt`, `slalomLineFast`), the second run set again on the same stretch; it publishes `Level.slalom` (`SlalomCourse`, with the `base` map it was set over) and `Checkpoint.pole` / `.turn`, and moves no generator digest. The analysis holds the course to R1–R24 like any piste (`analysis/index.ts`) and the area to R25–R30 once (`analysis/resort.ts`, with `access.ts` — `accessReport`, every piste's two halves and the island lifts — and `hub.ts` — the hub, the tunnels and the drags' lines).
- **`sim/`** — `bot.ts`, `simulate.ts` ([simulation.md](simulation.md)).
- **The generic pool is the framework's `core/`**: `prng`, `math`, `noise`, `heightfield`, `quat` (the one statement of the sign conventions), `solar`, and `output` — the central output module every line the engine prints goes through. `engine/index.ts` re-exports what a host reads of it.

## `pwa/` — the browser shell

A Preact app over a three.js renderer, built by Vite into `pwa/dist/` with a hand-rolled service worker (`pwa/pwa-plugin.ts`; the framework's update watch, read through `pwa/src/lib/pwa-update.ts`). It imports the engine as `@engine` and nothing deeper; it READS `GameState` and never writes one, and it never steps physics except through `step()`. Preact is spelled `react` (`pwa/tsconfig.json`'s `paths` alias it to `preact/compat`).

### The shell (`App.tsx`, `game/shell.ts`)

Seven SURFACES over one canvas and ONE engine state: `splash` (the attract card), `menu` (the front door), `loading` (a run being stood up), `pause` (the run held), `run` (the player on his skis, the HUD over the top, the finish plate over that once the finish line is crossed), `replay` (a run being WATCHED, stepped off its tape — `watching`) and `bench` (DEVELOPER ▸ BENCHMARK timing its pinned race: the benchmark's pump steps and draws it, so the app's own loop does neither — `appDraws`). `shell.ts` is DOM-free and says what each one means — who skis the state (`botInput` under a card, the input manager under a run: `playerRides`), whether the engine steps at all (`simulates` — false under the pause card and the bench), whether the HUD is drawn (`hudOver`), whether the run's events make a sound (`soundsLive`) and which camera a surface is seen through (`cameraFor` — the slow orbit under a card). `App.tsx` decides only WHEN one surface gives way to the next. **The snow never stops behind a card except the pause card**: the front door stands over a live run the bot is skiing, and leaving a run for it hands the same skier back to the bot rather than tearing anything down.

- **The clock** — the framework's `loop/run-clock` (§37), driven from `App.tsx`: `requestAnimationFrame`'s time into whole fixed steps of `TUNING.dt`, the frame delta clamped and the excess dropped, a hidden tab pausing the run, and the leftover fraction handed to the renderer as `alpha` for interpolation only. Each step samples the input once (`input.ts`) and calls `step`.
- **Standing a run up** — `game/run-loader.ts` sequences a load into phases, each spending a share of a frame (DOM-free); `game/app-load.ts` is what the phases ARE (generate the mountain, stand the field, build the terrain, the forest and the gates, compile every shader) as a factory over `App.tsx`'s closures. The renderer is FETCHED behind the attract card (`import("./game/renderer.ts")`), so three.js is not on the first-render path.
- **The URL** — `game/url-params.ts` states every parameter the app reads (`seed`, `region`, `start` — `slalom` (or `race`, or `1`) or `free` — `mode` — `trial` or `tricks` — `run` — a slalom link's second run — `t`, `pose`, `hold` — a ride held at a speed in a move, `hold-input.ts` — `shot`, `paused`, `camera`, `skis`, `menu` — including `gallery` and `dev` — `bench`, `splash`, `update`); [configuration.md](configuration.md) is the table.
- **What is remembered** — `game/settings.ts`: the camera rung, the skis picked, the outfit worn, the sound switch, the HUD switch (H) and every OPTIONS row, merged field by field (`mergeSettings`). The ski card (`menu-skis.tsx` over `ski-picker.tsx`, its turntable `ski-turntable.ts` fetched as its own chunk, its sheet `ski-stats.ts`, and its CUSTOMIZE SKIER press to the DRESS card, `menu-dress.tsx`, whose rows step `outfit.ts`'s catalog), OPTIONS (`menu-options.tsx`) and its KEYS page (`menu-keys.tsx`) are the `menu` surface's pages, the last two built from `menu-knobs.tsx`'s rows. So is the FREE RIDE's start card (`menu-start.tsx`): its answers are `free-ride.ts`'s (DOM-free — what is stored, and `freeGameOptions`, the one place they become a run), and its chart is `seed-preview.tsx` over `seed-preview-worker.ts`, which generates the mountain off the main thread and bakes its ground with the minimap's own `bakeMinimap`, with `seed-chart.ts` (DOM-free) cutting the piste, the start line and every kicker for the summit-up PLAN and mapping a tap back to the snow, and `panorama.ts` (DOM-free) painting the PANORAMA — the mountain from out over the valley, an orthographic view marched column by column with a running horizon — and cutting the ski area's runs, lifts and marks against its depth, and its pick grid turning a tap back into the snow.
- **What the picture costs** — `game/settings-video.ts` (DOM-free): eight ladders and the presets over them; `renderer.setVideo` applies a picture live (the ground and its trail maps are REBUILT for a TERRAIN or TRAILS row; ANTIALIAS is read only when the canvas is made). `game/video-probe.ts` times a first visit drawing MEDIUM and `picture-fit.ts` fits an untouched picture to sixty frames a second off `PICTURE_PRICES`.
- **The trick maps** — `game/trick-maps.ts` (DOM-free): the six maps a TRICKS run skis, each a seed with its terrain park on a generator version and a digest (`tests/trick_maps_test.ts` holds both), skied on a date, an hour and a sky of its own; the trick map card (`menu-tricks.tsx`, routed with the campaign and level cards by `menu-pinned.tsx`) picks one, `Settings.trickMap` remembers it, and `pinned-run.ts`'s `tricks` stands the run up behind the loading card. The render stack itself arrives through `use-render-kit.ts`, the one dynamic import of `renderer.ts`.
- **The developer page** — let out by holding the front door's title for seven seconds (`menu-hold.ts`); `menu-dev.tsx` is the page, `dev-tools.ts` drives its instruments every frame (the frame rate, the renderer's own `FrameCost`, the physics' stations, `trail-overlay.ts`'s maps in the corner, the engine log, `free-fly.ts`'s camera), `debug-hud.tsx` draws them over the picture with the REPRO line (`debug-readout.ts`, DOM-free) at the foot, and `dev-app.tsx` is the whole of it `App.tsx` sees. UNLOCKS sets the campaign's board by hand (`campaign-unlocks.ts`).
- **The benchmark** — `benchmark-plan.ts` pins the race (a seed on the current generator, the whole field, chase, a fair late morning, 1800 frames at a sixtieth); `bench-run.ts` stands it up behind the loading card with its lights counted out there as the warm-up; `benchmark.ts` pumps its frames through a MessageChannel with a one-pixel fence on each, billing every frame its whole period; `benchmark-index.ts` scores it (100 is real time), `benchmark-report.ts` writes the report (`FrameCost` is stated there so the suite can read it without three.js), `scene-tally.ts` walks the scene once at the end, and `benchmark-history.ts` keeps the last twenty runs whole.
- **One button, wherever pressed** — `game/run-actions.ts`: a key, a HUD thumb or a desktop menu-bar row (`shell-host.ts`'s `sh-shell-command`) all land on one handler.
- **The shutter and the gallery** — `game/shot-request.ts` takes a picture in two halves: at the PRESS it reads the caption (`run-news.ts`'s `shotLabel`), rasterizes the HUD (the framework's `shots/shot-hud`: the live chrome serialized into an SVG `<foreignObject>` with the page's own stylesheet, cards left out) and claims the clipboard; at the FRAME, right after `renderer.draw` in the same task, it lifts the drawing buffer (`screenshots.ts`'s `grabFrame` — the context keeps no back buffer), then stamps the mark and encodes the PNG. What is DECIDED about a picture — its size, its name, where the stamp goes, the HUD layer as a document — is the framework's `shots/shot-plan` (DOM-free). The roll is its `shots/shot-roll` (the policy, storage-free) over `shots/shot-store` (IndexedDB, in memory where there is none); `menu-gallery.tsx` is the viewer, with thumbnails shrunk off the main thread (`shots/shot-thumbs`) and the three ways out in `shots/share-image`.

### The picture (`game/renderer.ts`)

The one thing `renderer-api.ts` promises the shell, built from modules that each own a part of the picture. Everything that depends on the map is built in `load`; `draw` only moves things. Every skier is drawn `alpha` of a step on from the step before (`interp.ts` reconstructs the previous pose the engine does not keep).

- **The ground** — `terrain.ts`: a camera-centred CLIPMAP of nested grids (a quarter metre a vertex at the lens, doubling per level, eight levels past the ridges), nothing baked into the mesh: the vertex shader reads the generator's heightfield out of a float texture and morphs each level's edge onto the next. A ground map (gradient, packed, wooded) and the piste's direction ride beside it.
- **The snow** — `snow-glsl.ts`, grafted into a `MeshStandardMaterial`: the slope read per pixel from the gradient texture, wrap lighting with a blue terminator, world-space GLITTER, the groomed piste greyer and combed with corduroy, a fine grain of patches a hand to a couple of metres across close in (the texture the eye reads pace off, faded before it aliases), the rock on the steep faces above the tree line, the forest tint past the far band, and snow painted brighter than white (`GLARE`) so a low sun does not arrive grey.
- **The tracks** — `trail-stamp.ts` (three-free) turns every skier's `SkierState.contacts` into capsules from the last touch to this one, at the physics' sink or the powder's own furrow, whichever is deeper, cut narrower and deeper the more edge the ski stands on; `trail-map.ts` keeps them on the GPU in world space — a COARSE map over the whole mountain for the life of the run and a FINE window round the player — with MAX blending, and the terrain lowers the snow by it and shades the trough. A thrown skier's slide gouges a wider furrow of its own (`bodyStampOf`).
- **The woods** — `forest.ts`: every `Level.trees` trunk drawn as the kind it is (`TreeDef.kind`: twenty kinds, conifer and bare broadleaf) in one of that kind's ten VARIANTS (`tree-variants.ts`, three-free: the numbers and the silhouette `crownAt`), every one BUILT PROCEDURALLY by `tree-shapes.ts` over `tree-mesh.ts` — chunky, faceted, low-poly — at three levels of detail (full, mid, far) and painted per map in the region's colours; its trunk is drawn to the tree's own GIRTH, the engine's `TreeDef.radius`, which grows with its AGE (R14): every trunk vertex carries a stem tag and every instance its girth, and the vertex shader (`tree-mesh.ts`'s `graftGirth`) widens the ring about its axis, so a sapling and a veteran of one height stand side by side at no cost in meshes. One instanced mesh a shape the map grows: FOREST's rung is how many VARIANTS of each kind are drawn (ten, five or two — never fewer kinds), each at the full and the mid cut, and the far band and the casters draw one shape a kind; in three bands of distance (the full tree, the mid cut of the same variant, then a sketch), binned into 64 m cells and frustum-tested per frame; a tree crossing a band's edge is never swapped in a frame but DISSOLVES into its next cut over 0.4 s, both cuts drawn under complementary screen-door dithers (`tree-bands.ts`, three-free: the hand-over, its hysteresis, and a tree first seen taking its cut at once), so a lens at rest leaves every tree whole; what CASTS is a separate, shadow-only set — every tree whose shadow can land in the key light's circle, in front of the lens or behind it (`shadow-box.ts`), so no shadow is switched on by skiing nearer its tree. Nothing grows above the tree line (R14, an altitude the region sets) and the krummholz band under it is stunted.
- **The wildlife and the marks, built** — every bird (`bird-shapes.ts`), animal (`beast-shapes.ts`) and mark of the course (`mark-shapes.ts`) is built procedurally on the trees' bench (`tree-mesh.ts`'s `Shape`: keyed lofts, flat-coloured faces lit half by their own normal and half by the part's mass, and MARKS on the vertices the shader moves — a wing's flag, a leg's phase and hip, the head, an antler's root and the age its tine comes at), at a near and a far cut. Who each animal is — its form, size, shade and rack — is `wild-traits.ts`, a pure hash of its group's own scatter; `birds.ts` and `beasts.ts` draw one instanced mesh a species form and cut, and the FOREST row (`FOREST_LOOK[row].wild`) says how many forms are drawn and where the cuts hand over.
- **The region** (R21) — `region-look.ts` (three-free): what a kind of snow country is painted — the wind crust, a tarn's ice, rock on the steep faces, the sastrugi, the rime, the far woods' tint, the trees' needles and bark — read by `terrain.ts` (a fourth, SURFACE map of the engine's `Level.crust` and `Level.ice`) and `forest.ts` (the kinds' needles, bark and snow load off the region's). `colour-grade.ts` (three-free: the model) and `grade-pass.ts` (the GLSL) are the GRADE over the whole finished frame; `region-picture.ts` is the one place a frame reaches the canvas: straight for the alpine, whose grade is the identity, or drawn into a half-float target that the pass tone-maps, grades and writes out.
- **The course** — `gates.ts`: each gate a pair of slalom poles with a panel between them, red and blue alternating — on a resort's course a slalom gate set off the line, narrower than the piste — the next one loud and breathing a little light; edge poles along both sides of every run on the mountain, in its colour; the start hut with its wand over the start gate; the FINISH an arch over the finish line with the arena's fences and banners and the line dyed on the snow under it (`start-arch.ts` is its plan, shared with `camera-clear.ts`). On a slalom (`Level.slalom`) the gates are `slalom-poles.ts`'s FLEX POLES instead — red and blue, no panel, each lying over as `GameState.gatePoles` says and swinging back, the owed gate breathing and its marker over the turning pole — the safety nets line the whole course, and the start is a START HOUSE (`start-house.ts` over the three-free `start-house-plan.ts`, which `camera-start.ts` and `camera-clear.ts` read too: the billboard front, the narrow dark doorway, the wand on its posts swung open by his shins, the start clock in the jamb red until GO and counting the starter's word, the two pole holes trodden outside the posts); the house's fascia and the arch's span carry their word on `banner-texture.ts`'s banner.
- **The lifts** (R26) — `lift-plan.ts` (three-free): where a lift's towers stand along its straight line, how tall, every span aimed for its kind's spacing and shortened to clear a crest, and where the rope hangs between them with its sag; `lifts.ts` draws every lift of the resort off it — the towers and their crossarms, the stations and their bullwheels, the up and down rope as lines, and the gondola's cabins, the chair's chairs or the drag's T-bars hung where they stand — a dozen draws for the mountain, each part one instanced mesh.
- **The lifts and their stations** (R26) — `lifts.ts` draws every lift off the engine's plan (`lift-line.ts`): the towers, the rope, and the chairs, cabins and T-bars MOVING on it where `carrierAt` has them at the engine's clock — on every map in every mode — and, while the player rides a chair, his own chair hung under him (once he is off, running on empty round to the wheel, left out of the frame while it stands between the lens and him); the station houses stand where `stationHouses` has them (a chair top's beside its way off); `station-plan.ts` (three-free) lays out what stands at each station off the research in [summit-stations.md](summit-stations.md) — the terminal hoods, the operators' booths, the stop gates, the netting, the wind masts, the run signs at a chair top's parting (`signsOf`), the patrol hut and the map board on the highest top, the load lines, the corrals and the stations' doors — and `station-parts.ts` builds them, one instanced draw a kind (a sign's board one a grade). The rider sat on a chair is `skier-seat.ts` (the pose `skierPose` stood him in, sat back against the chair's backrest), a rider in a cabin out of sight; the lens at a summit is `camera-summit.ts`, and how close it rides a lift and lets him go through the unload `camera-lift.ts`.
- **The wind tunnels** (R30) — `wind-tunnel-plan.ts` (three-free): where a point on a tunnel is, whether a skier is in it or beside it (`tunnelNear`), and how far the arches, the chevrons and the streaks are drawn from the lens; `wind-tunnels.ts` draws every tunnel of the resort off it — the arches with their chasing rings of light, the translucent canopy, the chevrons on the snow, the fan in its cowl at the entrance and the snow blown down the lane — eight draws for the lot, moved off the engine's clock. The minimap marks them (`minimap-view.ts`) and the news says so going in (`run-news.ts`).
- **The skiers** — `skis-body.ts` (the two skis with their bindings and boots built in the engine's body frame off `defs/skis.ts` and the class's traced look in `ski-looks.ts`, each pair in its own topsheet) and `ski-gear.ts` (the poles, and what moves — the skis turned by `skiAngle`, tipped by `edge`, each riding its leg's compression; the poles planted at a crawl and tucked under the arms in a tuck) laid ON THE SNOW by `ski-stand.ts` (the body turned about its feet rather than its centre of gravity by the engine's `incline`, the inside ski lifted toward him and the outside let down, the stance and the skid's pivot taken in the snow's plane, so both skis stay on the snow through a turn and a stop; and each ski's share of the load — the outside one's, by speed — which the spray and the snow cloud throw by — and shaken at speed by `ski-chatter.ts`, each ski hopping, its tip flapping and its edge rocking on the snow passing under it by the engine's `SkierState.chatter`, the knees taking it) with `skier-figure.ts` hung on the joints `skier-pose.ts` solves (three-free: each shin held in its boot and the knees folded by the legs' compression, a carve an inclined column angulated at the hips with the shoulders counter-rotated and the eyes held toward the horizon, entered upper body first — the head, the hips and the shoulders into the new turn ahead of the knees (`leadOf`), the weight fore and aft with the lean, the crouch of the tuck with the back rounded, compact in the air and riding a FALL by how far it is — `skier-flight.ts`: secure off a kicker, spotting a drop, windmilling a cliff, reaching for the snow, staged by the seconds he has been HIGH over the snow and timed off where his flight meets it (`flightRead`, the map handed to each model by `setGround`) — the grabs, alive when stood still; the legs leaning with the skis' edge and turned with their pivot, a pole planted on every new turn at speed; the gait at a crawl is `skier-gait.ts`'s (with how much he works the poles — none once a stroke cannot keep up with the snow; out of a slalom's start house its `launchGait`, the push through the arms, under the SLALOM START CLIP — `slalom-start.ts`, three-free, keyed by `SkierState.launch`: held crouched in the door, the chest out over the wand, the heels kicked back and up and both skis fired through, `kickStand`, then into the racing stance), the arms' strokes, the push held to the snow (each basket kept where it bit) and the turn's plant `skier-stroke.ts`'s, the limbs' geometry (two bones toward a target, the boot's frame and the knee its cuff allows, the pelvis tilted up over the higher ski and the hips lifted so no knee folds past a skier's, the trunk folding at the hip instead) `skier-limbs.ts`'s, the mounts `skier-mounts.ts`'s, and the view's own state between frames — the upper body as a mass of its own on the legs as springs (damped against the line he rides, so the knees take a roller and the head rides on, and a landing folds him into the knees), the trunk's pitch held while the skis rock under him, the air and a jump's load eased, the hips' shift, the edge and the roll followed, the upper body's lead into a turn, the plant timed, his own clock — is `skier-spring.ts`'s), DRESSED in his outfit (`outfit.ts`: a body, a jacket, pants, a helmet, gloves and poles, each sold in its own colours): every piece cut to the body's measure (`dress-body.ts`, the anthropometric survey's man or woman on the one skeleton) plus its ease on a loom laid in the rig's bind pose (`dress-loft.ts`; the jackets and pants `dress-garments.ts`, the helmets over the three-free `helmet-shape.ts`, the braid and the gloves `dress-head.ts`; cut once and kept, `dress.ts`) and skinned on the rig's bones (`skier-dress.ts`, posed by `skier-rig.ts`'s `skierBones` of the very pose the poles hang on), so the cloth bends with every pose as one skin and nothing is drawn under it. Thrown (`SkierState.thrown`), the figure is hung on the engine's ragdoll (`skier-ragdoll.ts`'s `ragdollPose` reads its trunk's frame and every joint off `Thrown.points`) and laid in the root's frame at that place and turn, so the one merged draw still carries him while the skis slide on without him; `interp.ts` carries the points between two steps, and `trail-stamp.ts` presses every bone of him into the snow. Where a build carries the models, `skier-models.ts` hangs the Blender pair beside the code's and collapses the code's drawn skis out of the merged draw (`posed-merge.ts`), posed by `ski-rig.ts` off the same readings. The dressed skin is drawn apart from the merged draw (two skinned meshes: the cloth and the hard goods) on the rig's bones: the trunk in two, a half-angle bone at every hip, knee, shoulder and elbow, each hand closed round its pole, each foot in its boot's liner — hidden in the shell on the skis, on the ends of his legs when he is thrown.
- **The air** — `sky.ts` (three-free): the sun at the map's hour (`sunAtRun` — it stands still over a run), its colour through the air mass, the dome's zenith and horizon, the blue hemisphere light that makes shade on snow read as snow; `haze.ts`: one sky function in GLSL that the dome paints and every far surface fades into along its own direction; `sky-dome.ts`; `environment.ts`: the lights, and one shadow map over a circle a SHADOWS row's reach round a point ahead of the lens (`shadow-box.ts`), snapped to whole texels and faded out over its rim by a graft in `hazeMaterial`, so the map's edge is never a line. Over the whole map lies the MOUNTAIN'S OWN SHADOW: `terrain-shadow.ts` (three-free) bakes, once a map and again only when the key's bearing moves, the horizon every texel of a grid over the map sees along the key's bearing (a convex-hull sweep of the engine's own heightfield, four metres a texel on a three-kilometre map), `terrain-shade.ts` asks it of a worker (`terrain-shadow-worker.ts`) and uploads it, and the same graft takes it with the key's map — the darker of the two, so a ridge's shade is the same sky-lit blue as a tree's; and every caster draws its depth through `shadeDepth`, which throws away what the mountain already shades, so a skier on a face turned from a low sun throws no shadow onto the next sunlit crest. Every SHADOWS stop but OFF draws it. The WEATHER is R19's (`Level.weather`, read through `weatherOf`) and the NIGHT the clock's (`moonAtRun` beside `sunAtRun`): `skyLookFor` lays each over the clear day — a lid's flat light and grey dome, the haze a fall or a fog thickens, the stars, the moon as the key light — and says how flat the light is (`flat`, which the snow shader answers with its last relief), how much the snow glitters, and how far on the lamps are. The dome draws the cloud (heaps, streaks or a lid, carried by the wind), the night sky (`starfield.ts`: the stars sized in pixels on the sphere the map's hour, day and latitude have turned, and the Milky Way) and the moon's disc; a fall closes the haze to the view `snowAt` leaves, and the new snow (`GameState.fresh`) buries the groomer's look (`snow-glsl.ts`'s `uFresh`) and fills the tracks (`trail-map.ts`'s `fill`); `snowfall.ts` the fall round the lens (and under a sky that is not snowing, the air's fine ice crystals near the lens, the one thing in open air close enough to stream past at pace) — every flake drawn as the SMEAR it sweeps over the frame's shutter, its velocity past the lens being its own (the wind and its fall) less the lens's, which is measured off the lens frame to frame (`snowfall-plan.ts`, three-free), so at 100 km/h into still air the snow comes at the lens at 100 km/h, rushing out of where the skier is heading, and a planted lens sees it only fall; `make snowfall` rides the ladder of speeds under every falling sky — and the spindrift off the crests, both carried by `windAt` — a pure function of the map and the clock, drawing nothing from the run's stream; at night the finish arena's FLOODLIGHTS stand over the run-out (`gates.ts`'s floods) and every skier wears a HEADLAMP on his helmet (`headlamp.ts`: a narrow spot and a wide flood round it, turned with his head), dealt to the `LAMP_SLOTS` by `dealLamps` — the player's first, then the floods, then the field's — each slot its own colour and beam, read through one function (`haze.ts`'s `lampReach`) by the snow's lamp term (`snow-glsl.ts`, with its glitter), every `hazeMaterial` (the woods, the gates, the skiers), the falling flakes and the snow cloud. And down every run stand the PISTE LIGHTS (`piste-light-plan.ts`, three-free: the floodlight masts laid out as a lit piste is — about fifty metres apart on one side, both past seventy metres of width, a light point of ten to eighteen metres by the width, each lamp an asymmetric 4000 K flood aimed down and across the run and cut off above its aim, sized for 30 lx so the recreational class of the sports-lighting standard holds, 20 lx on average and never under 4, while the snow past the edge stays dark; `piste-lights.ts` draws the masts in four instanced draws and their haloes in one): too many lamps for the slots, and still, so their light is BAKED once a map the first time the lamps come on — the vector irradiance on the ground over the whole map, four metres a texel, a crest between a lamp and the snow its shadow — and read through `haze.ts`'s `pisteLight` by the same four. `make sky` is the whole ladder on one sheet.
- **The crowd** — `crowd-view.ts` (and on the lifts: stood in a queue, sat on a chair — the `seat` target, the player's own seated pose — behind a T-bar on the snow, out of sight in a cabin): the free ride's amateurs, one instanced mesh a body and cut (`crowd-shapes.ts`: eight procedural bodies at NEAR, MID and FAR) holding whatever of that body is in sight, each posed by the weights of its morph targets — every target the player's own `skierPose` solved for that moment and sized to the body (`crowd-rig.ts`), so the crowd moves when the player's animation does, and run through the player's own animations on his timing (a pole plant on every turn he begins, by the player's plant rule off the engine's `Amateur.turnSide` / `turnT` / `turnHeld`; stood still, the player's wait, swung one way and the other on his own clock) — and dressed per instance from one palette (`crowd-dress.ts`). Reads the engine's `GameState.crowd`, writes nothing; `make crowd` is its lab.
- **The spectators** — `spectators.ts` over `spectator-plan.ts` (three-free: who watches a run with something to watch — the slalom, the time trial, the tricks run — and where each fan stands: the finish arena's grandstands, terraces and slope, the jumps, the inside of the hard turns, the pitches, the corridor, the start; on a slalom `spectator-slalom.ts` (three-free) lays them behind the nets (`NETS`, `netStretch`) on both sides of the whole course, thickening down to the finish, crowding the combinations and the steepest pitch, a few beside the start house; dealt off the map's seed on a generator of its own) and `spectator-shapes.ts` (one rough figure at three cuts carrying every hat and prop, folded away per fan, and the shader that moves him off `state.t` and where the racers are): one instanced mesh a bank and cut, the finish arena's furniture beside them (`finish-arena.ts`). `createPeopleView` hands the renderer the free ride's amateurs and the spectators as one view. Reads `GameState` and the `Level`, writes nothing; `make audience` is its lab.
- **The wildlife** — `wildlife.ts`, the birds and the animals behind one door. Presentation end to end: every flock and every group is dealt off the map's seed on a generator of its OWN (`bird-roost.ts`, `beast-plan.ts`, salted so nothing in the engine draws the same stream), reading only what the `Level` publishes (`wild-ground.ts`: the nearest trunk, the piste, the drawn snow, the tree line) and writing nothing back, so no map's digest and no run's stream can see a bird. Where anything is at a moment is a pure function of the clock — `birdPose` (the cycle of rest and flight, the circuit, the wings hinged in the shader; the skeins crossing in March, `crossingAt`) and `beastPose` (a round walked in a closed-form cycle of standing and moving, the legs and the head moved in the shader) — and the two memories are the renderer's, each decided by a rule stated once: `flushAt` (a covey put up by any skier, which the audio keeps too) and `spookAt` (a group that runs from a skier and stays where it ran to). The animals' PRINTS are stamps in the same trail map as the tracks (`beast-tracks.ts`): one lap of each round laid when the run starts, laid again at the fine map's grain whenever its window moves, and new ones behind an animal that has fled. The rosters and the rarity ladder are `bird-defs.ts`, `beast-defs.ts` and `rarity.ts` — every row names the regions (R21) it lives in and a map lays only its own region's rows (the alpine's choughs and chamois, the fell's reindeer and ptarmigan, the continental's elk and bighorn, the maritime's serow and sea eagle — species, never places); the look `bird-shapes.ts` and `beast-shapes.ts`; `make birds` is the whole roster on one sheet.
- **What the skis throw** — `spray.ts`: the sheet off a skidded turn, the powder off the tips and the tails in a carve, the landing puff — the HEAVY part, grains and clumps, one pool of sprites lit as the snow is (a clump harder-edged, shaded and falling faster). A wipeout adds its BURST, a puff each time the thrown body comes down on the snow and a plume while it slides (`renderer.ts`'s `thrownEffects`, `spray.burst`, `cloud.burst`).
- **The snow cloud** — `snow-cloud.ts`: the FINE powder the same moments raise, which stalls behind the skier, swells, drifts on the wind and settles for seconds. One instanced draw of camera-facing puffs for every skier, sorted back to front, each shaded as a small volume: a noise-carved body torn into wisps as it ages, the sky's light wrapped round it, the whole cloud's shadow on itself (the puffs walked sun-first through a hashed grid across the sun's rays, with a multiple-scatter octave), a Henyey–Greenstein glow against the sun, glints, the floodlights' cones, a soft meeting with the snow and the haze. The chase lens sees through the player's own tail (`setFocus`'s veil); a planted lens sees it whole. What each source throws out of which snow, and how a puff flies, is `snow-cloud-plan.ts` (three-free) — and how much of it is LOFTED at a speed (`loftOf`: a crawl shoves the snow aside and it falls back; the fine cloud fills in with speed), so the rooster tail is a plume at speed and next to nothing at a walk.
- **The kinds of snow** — `snowpack.ts` (three-free): groomed, hard (the wind's crust and slab), soft (settled powder), new, wet and ice, blended at a point off the map's packed field, its crust and its ice, the new snow a snowing sky has laid and the run's `fresh` on top, and a spring thaw under a high sun. The renderer builds one `Snowpack` per run (`packFor`; a lab forces a kind with `setSnow`) and every reader samples it: the cloud and the spray (how much, how fine, how clumped), `trail-stamp.ts` (a groove's depth, its walls — `Stamp.wall`, the power of the cross-section in `trail-map.ts` — and its windrow), `beast-tracks.ts` (how deep a print goes, a crust carrying a light foot). Presentation only; the engine's snow is its own.
- **The lens** — `camera-rigs.ts` (three-free: the ladder `tips`, `helmet`, `chase`, `far`, `high`, and `orbit` for the cards) and `camera.ts` (the rig on a three.js camera, and a flown hand-over between rungs). A boom is hung on second-order springs (`camera-spring.ts` — a natural frequency, a damping ratio and a response per reading, which place its two poles): its yaw, its height (told the descent the fall line predicts, so a steady schuss is tracked without lag and only the rollers are smoothed), the fall line it leans to and the pitch of its look. It reads the fall line ahead of the skier, swings the arm up the slope behind him by a share of it (`incline`) and COMPOSES him at one place in the frame (`place`, a share of the half-fov under the axis) on every pitch — so the look tips down an ordinary piste by about half its pitch, so the drop under the skis reads, and further on the steepest faces (`inclineSteep`), so the piste ahead still shows over his head, never all of it, and the horizon stays near the top of the frame; a guard (`frame`) tips the look after a drop no spring can follow. On top of the framing, `PACE` folds in the sense of speed: the fov widens with pace while the boom pulls in along its line (`hold`), so the skier keeps his size and the mountain rushes past the edges; the arm falls behind a skier pulling away and swings in over one skidding (the surge); and past a brisk pace the lens buzzes — harder on the hard snow, still the moment the skis leave the snow (the tremor). While the player is thrown, `camera-death.ts` (three-free) takes the lens off the ladder: it flies after the body (drawn between two steps by `interp.ts`'s `BodyTrack`), closes in on him at full speed (the run is never slowed for a wipeout; the replay's director is the only time rate) and, once he lies still, tilts down on him and rises into the sky, swaying, until the reset cuts back to the ladder. On a slalom `camera-start.ts` (three-free) takes the lens for the START as television shows it: OVERHEAD over the door for the first two seconds of the starter's word, then BEHIND the racer inside the house looking out of the door down the course; on the wand it follows him out (0.7 s) and flies onto the player's rung (1.4 s) — a pure function of the clock and where he is, so a restart, a replay and a pause frame alike.

### What is read and pressed over a run

`hud.tsx` draws a DOM-free snapshot (`snapshot.ts`, taken ~12 times a second): the run clock, the position, the gates taken of the total and the split top left, the air clock top centre, the lights and GO in the middle (on a slalom the RUN — 1 / 2 — where the position was, the starter's READY and GO small at the top centre and out of the start shot, and at the course's two timing points the split and the gap to the LEADER there, green ahead and red behind — the snapshot's `slalomOf` over `slalom-board.ts`'s `timingGates` and `timingSplit`), a missed-gate arrow, the EDGE bar over the speed bottom left (`hud-dial.tsx`: how far over the skis stand, with the skid's word on it while the brake is on), the WIND METER to the right of the speed (`hud-wind.tsx` over the snapshot's `windOf`: the weather's wind and the wind the skier feels — the engine's `airflowAt`, the wind less his velocity — each as an arrow on a heading-up dial, the felt one in km/h), the news column bottom right (`run-news.ts`, pure — a wipeout and how he fell, a bog and how to pole out, a dulled edge are news too), BOGGED where the missed arrow stands while he is sunk in, the DAMAGE instrument beside the speed on a run with damage on (`hud-damage.tsx`: the two edges and the legs), THE BODY at the left edge (`hud-body.tsx` over the DOM-free `body-tile.ts`: an anatomy plate from the front — the outline traced off a photograph and cut into the twenty parts (`body-figure.ts`), each part's flesh painted by its worst injury that is not a fracture, the bones traced off a public-domain skeleton plate (the generated `body-bones.ts`, `make anatomy`) whole, cracked by a fissure or broken through with its fragments displaced (`fractureOf`); the word for the whole of him off the injury severity score, only what the bones cannot show in plain words — `strings-body.ts` — and the run's hardest blow), THE G METER over the skier the moment a blow lands and someone goes down on it (`hud-gforce.tsx`, shaking by how hard it was), the combo line over the tips on a tricks run (`hud-combo.tsx` over `trick-tile.ts`), and top right, over the presses, the MINIMAP (`minimap.tsx`) — pressed, it pauses: the map turned heading-up about the skier, its window opening with speed, every run of the resort in its colour and every lift under the raced piste, every gate with the owed one marked and a chevron on the rim when it is off the plate, the finish, and the field in its slot colours (`skier-colours.ts`). The ground under it is painted once per map — hillshade, contours, rock on the faces too steep to hold snow, the packed piste, the woods as a green mass and every tree in it — by `minimap-bake.ts` in `minimap-worker.ts` (on the main thread where a worker cannot run), started as the map is put into the renderer; `minimap-view.ts` is the DOM-free pose and marks, and `minimap.tsx` paints the world on a canvas, gliding between snapshots on the animation frame. `hud-actions.tsx` is the presses under it (reset and camera, with a pause disc heading the row only while the readouts are off and the map with them), fired — like the map — from `pointerup` (the framework's `input/hud-press`) because a skiing phone's primary finger is always on a control. `hud-result.tsx` is the finish plate — on a slalom which run it was, on the second both runs and the total, the gap to the leader, the SECOND RUN press or why there is none (`slalom-heat.ts`, DOM-free: `secondRunOf`, `heatAfter` — the first run handed to `createGame` as its heat — and `heatOf`, which a restart and a replay hand back so a second run stands up again as itself), and under it the BOARD (`hud-board.tsx` over `slalom-board.ts`'s `boardOf`: every racer by his bib in the engine's order, his times and his gap, the racers out of it billed DSQ or DNF and where, the player's row lit and scrolled to); a run that went OUT has a plate of its own, DISQUALIFIED or DID NOT FINISH and why. The slalom's words are `strings-slalom.ts`, spread into `strings.ts`. THE RECORD BOOK AND THE GHOST: `records.ts` (storage-free above its storage line) is the book — one row per seed, skis, mode and laps (and a slalom's second run a row of its own, `runKey`), with the clock at every gate the snapshot's `gap` is read against; `ghost.ts` is the tape — `snapInput` puts every axis on the tape's grid where the input is made (`input-model.ts`) and again where `App.tsx` hands the engine any input, and a `ControlTape` is five RLE'd, base64'd streams; `ghost-run.ts` is the rig `App.tsx` arms on every player's run before its first step, which files the run at the finish, keeps the time trial's record run as a tape, and steps the ghost — one more `GameState` over the same `Level`, on the recording's own skis and help — a step of tape per step of the player's. The renderer draws it through `ghost-model.ts`, see-through, casting no shadow and stamping no track. THE CAMPAIGN: `campaign-levels.ts` is the ladder (four shelves, each one SKI AREA — a seed on generator version 3 in its region — and six of its courses, every level pinned to its version and the digest of its map — `engine/mapgen/versions.ts`, `digest.ts`), `campaign.ts` the policy (storage-free above its line: the map built, `pinnedFor` — which map a SLALOM or a TIME TRIAL skis — the points, the locks, the table, the board), `campaign-run.ts` the rig `App.tsx` steps beside a run on a rung, which books it at the player's finish and writes the finish plate's lines, and `pinned-run.ts` the factory that stands a pinned run up through the loader and again on a restart, and a slalom's second run off its first (`secondRunOff` for a `?run=2` link; the rung is booked at the first run's flag). The cards are `menu-campaign.tsx` and `menu-levels.tsx`, with each map's piste drawn behind its box from `campaign-routes.ts` (generated by `make routes`). How hard a map is — `engine/rating/` — is dev-time only: the labs read it and the game does not. Input: `settings-input.ts` (which key is which action), `input-model.ts` (the ramps, the lever, the edge thumb and the one sign flip between screen and engine — DOM-free), `input.ts` (the listeners), `hud-touch.tsx` + the framework's `input/thumb-guard` (the two thumb zones and their grip). Every word is `strings.ts`'s (§39.1). THE REPLAY: `replay.ts` arms a recorder (the ghost's own `ControlTape` codec — one tape, never two encoders) on every slalom, time trial and tricks run at its first step, reads the afternoon off the run (`recipeOf`: the `Level`, which already carries the day, the sky and the region, the seed, the rules, the skis, the help, the damage switch, the snow dial, and on a slalom's second run its heat) and on WATCH REPLAY rebuilds it — checked against a fingerprint of the first step (`startPrint`) — so a field is dealt the same again — a line start's paces skied by the same bot to the same finish, a slalom's board. `replay-shots.ts` collects the moments off the player's events (a flight back-dated to its take-off, a pass off `racePlace` held for a second, a trunk, a rival, a wipeout, the finish), `planShots` ranks and spaces them, and `directAt(plan, step)` is the whole edit: which moment holds the frame and the TIME RATE — slow motion is fewer steps per frame and nothing else. `camera-tv.ts` plants the broadcast's lens at the edge of the wood beside the kicker, the arch or the spot, kept out of the trunks and the crowns by `camera-clear.ts`; the renderer applies it through `setShot` (`replay-run.ts` pushes it, on the `tv` rung of `WATCHING_CAMERAS` only). The adopted state is fresh, so the trail map starts from empty and is stamped again as the replay runs; `hud-replay.tsx` is the bar over it.

### The sound and the hands

`game/audio/` — every sound synthesized on one WebAudio instrument (the framework's `audio/synth`, under two faders in `bus.ts`) from authored parameters: the event one-shots (`bank.ts` routed by `route.ts`), the wind and the snow as steered layers (`wind-voice.ts` — the rush in the helmet rising with speed and closing in with the tuck; `snow-voice.ts` — the edges' hiss, chatter and scrape and the powder's whoosh; `ride-bed.ts`, which also raises the poles' clicks at a crawl), the wind tunnel's gale, body and fan (`tunnel-voice.ts`, off the same plan the picture is drawn from), the birds' cries off the same plan the renderer draws (`bird-voice.ts`, `bird-bed.ts`), heard from the camera's seat (`listener.ts`). There is no engine voice and no music. [audio.md](audio.md) is the account. What is FELT is `rumble.ts` (which moments are worth a pulse, DOM-free) over `haptics.ts` (the one motor: the Vibration API, or the store app's haptics through `shell-host.ts`).

## `tests/` and `scripts/`

Root vitest suites, one topic a file (`skier_test`, `flight_test`, `collision_test`, `course_test`, `crash_test`, `rivals_test`, `determinism_test`, `simulation_test`, …). The physics is staged on the SYNTHETIC maps in `tests/support/synthetic.ts` — a slope with a packed piste, a kicker, rollers and a lone tree, and flat drag strips on a grade of their own, packed or powder — so the rule suite passes with the generator deleted; `simulation_test` also skis generated mountains, `mapgen_test` holds the course a generated map is raced on to R1–R24 and `resort_test` the ski area round it to R25–R30 in every region (sharing their maps through `tests/support/levels.ts` and asking `tests/support/resort.ts` which runs cover a spot).

The app's DOM-free halves are tested the same way (`hud_test`, `minimap_test`, `input_model_test`, `menu_system_test`, `audio_test`, `rumble_test`, `world_render_test` — the camera rigs, the skier's pose, the sky's colour model, the track's arithmetic).

`scripts/` is tooling and may import anything, every flag through the framework's `tooling/cli`: `npm run sim` (the balance table), `npm run ride` (the ride lab: scripted scenarios on the synthetic maps, numbers and a picture each to `previews/ride-*.png`), `npm run level` and `npm run analyze` (a mountain from above; a map scored against the rule book), `npm run world` (one seed skied by the bot and photographed through the renderer from its own harness page), `npm run skis` (the pairs and the skier on contact sheets), `npm run audition` (the audio review page), and `scripts/screenshot.mjs` / `profile-render.mjs` over the built site. The README's Usage table is the list.
